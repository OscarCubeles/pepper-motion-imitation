# Shared Evaluation Tools

This folder contains the tools used to annotate the recorded dataset, compute annotation angles, evaluate IK methods, and inspect the results.

## Dataset Structure

Each video is stored as:

```text
dataset/<category>/video_XXX/
```

Typical files:

- `video.mp4`: original recorded clip.
- `frames/frame_000.jpg ...`: extracted frames used for annotation.
- `annotations.json`: initial recording/template file.
- `annotations_filled.json`: main working annotation file. This contains Metrabs coordinates, manual corrections, hand orientation labels, and computed joint angles.
- `annotations*.legacy.json` / `annotations_filled.before_angles.json`: backups. Do not edit unless recovering data.
- `metrabs_visualizations/`: debug images generated by the Metrabs annotation script.

Be careful with `annotations_filled.json`: it is the manual ground truth and should not be overwritten casually.

## Dashboards

The interfaces for annotating datasets and inspecting evaluation results are
documented in the [dashboards README](../../../dashboards/README.md).

## Main Scripts

### Blur Faces in Dataset Frames

```powershell
python -m server.common.evaluation.blur_dataset_faces
```

This copies `dataset/` to `processed_data/`, preserving the folder structure
and annotation files while blurring detected frontal faces in every `frames/`
folder. Unblurred `.mp4` videos are skipped, and the original dataset is not
modified.

To remove `.mp4` files from an existing `processed_data/` folder:

```powershell
python -m server.common.evaluation.remove_processed_videos
```

### Run Metrabs On Dataset Frames

```powershell
python -m server.common.evaluation.annotate_metrabs_dataset dataset\pepper_singularity_motions
```

This fills shoulder, elbow, wrist, and torso coordinates in `annotations_filled.json` and optionally writes `metrabs_visualizations/`.

Useful options:

- `--overwrite`: replace existing coordinates.
- `--reset-from-template`: rebuild from `annotations.json`.
- `--no-visualizations`: write JSON only.
- `--max-frames N`: test on the first `N` frames.

### Record Synergy Reference Videos

```powershell
python -m server.common.evaluation.create_synergy_videos
```

This records webcam clips into the same dataset structure, using the default category:

```text
dataset/synergy_reference_motions/video_XXX/
```

Each recording creates `video.mp4`, `frames/`, and `annotations.json`. It does not create or overwrite `annotations_filled.json`.

Useful options:

- `--duration 15`: seconds per clip.
- `--fps 8`: frame rate for the video and saved frames.
- `--camera 0`: OpenCV camera index.
- `--category synergy_reference_motions`: output dataset category.
- `--no-preview`: record without the OpenCV preview window.

After recording, process the synergy category like any other dataset:

```powershell
python -m server.common.evaluation.annotate_metrabs_dataset dataset\synergy_reference_motions
python -m server.common.evaluation.compute_annotation_joint_angles dataset\synergy_reference_motions
```

### Compute Annotation Joint Angles

```powershell
python -m server.common.evaluation.compute_annotation_joint_angles dataset\pepper_singularity_motions
```

This computes:

- `shoulder_pitch`
- `shoulder_roll`
- `elbow_yaw`
- `elbow_roll`

Angles are stored in radians by default. `wrist_yaw` is not computed here and is treated as `0.0` for these annotation angle labels.

Useful options:

- `--dry-run`: preview changes without writing.
- `--overwrite`: recompute existing angle values after coordinate edits.
- `--degrees`: store angles in degrees instead of radians.
- `--no-backup`: skip creating `annotations_filled.before_angles.json`.

If coordinates are changed later, rerun this script with `--overwrite`; angles are not updated automatically.

### Evaluate IK Methods

```powershell
python -m server.common.evaluation.evaluate_ik_methods dataset\pepper_singularity_motions
```

This writes:

```text
dashboards/results/ik_method_metrics.json
```

The evaluator also fits the human synergy space used by the `SYN` metric from:

```text
dataset/synergy_reference_motions
```

Those reference videos must contain `annotations_filled.json` coordinates. They are used only
to fit one shared PCA model and are excluded from robot-method evaluation when the input is the
whole `dataset` folder. The default retains the smallest number of components that explain at
least 95% of the human-descriptor variance, with a maximum of five components.

Useful options:

- `--synergy-reference <folder>`: select a different human reference dataset.
- `--synergy-variance-threshold 0.95`: change the cumulative explained-variance threshold.
- `--max-video-index 5`: evaluate only `video_001` through `video_005` in every selected category. The synergy reference used to fit SYN is not limited.

Currently evaluated methods:

- `ground_truth`
- `current_solution_raw`
- `current_solution_constrained`
- `ikpy`
- `original_solution`

`original_solution` is evaluated through `original_solution_adapter.py`, which mirrors the cloned original arm-scaling math for offline use. The cloned code under `06-original_solution/` is left untouched.
`current_solution_raw` is the current arm-scaling output before runtime singularity handling. `current_solution_constrained` applies the same current runtime `PoseHandler` dual-singularity FSM in frame order. Elbow and shoulder singularity FSMs are still not applied because the current runtime `PoseHandler` only implements the dual-singularity branch.

Metrics currently included:

- `EEAh`
- `EEAr`
- `SOAx`
- `HJL`
- `WOM`
- `HJAr`
- `TSE`
- `SYN`

EEA metrics:

- `EEAh`: normalized human elbow elevation reference value from the annotated shoulder-to-elbow vector.
- `EEAr`: absolute elbow elevation error between `EEAh` and the method's reconstructed Pepper elbow elevation.

HJL uses `HumanArmClassifier`. During a ShoulderRoll or dual singularity, it checks the
method's ShoulderPitch/ElbowYaw pair against the side-specific piecewise-linear human
reachability envelope. A pair outside either reciprocal envelope is
`NON_HUMAN_DOABLE`. Frames without an applicable singularity receive a valid HJL value of
zero.

HJL is one binary value for each complete two-arm frame: `NON_HUMAN_DOABLE` on either arm
produces `1`. Frames missing any required shoulder-pitch, shoulder-roll, elbow-yaw, or
elbow-roll value are excluded from the ratio and reported as invalid. Per-frame classifier
results, causes, and per-sequence valid, invalid, and violating-frame counts are preserved in
the output JSON.

Current WOM logic:

- Human reference label comes from `left_arm/right_arm.wrist_orientation` in `annotations_filled.json`.
- `current_solution_raw` and `current_solution_constrained` WOM rerun each saved frame through the live MediaPipe hand-landmark, EMA smoothing, palm-normal, and dominant-axis label path. A valid label is retained independently for each hand within the video. When detection is missing, WOM reuses that hand's most recent valid MediaPipe label; if none exists yet, it derives a Pepper hand label from that method's joint angles through forward kinematics with `WristYaw = 0.0`. Each frame records whether its effective label came from `mediapipe`, `previous_mediapipe`, or `fk_zero_wrist_yaw`.
- `ikpy` WOM derives a robot hand orientation label from Pepper forward kinematics using IKPy joint angles; it does not copy the human/current-solution label.
- `original_solution` WOM also derives a robot hand orientation label from Pepper forward kinematics because the original solution does not provide the modern hand-orientation label.
- IKPy still uses `wrist_yaw = 0.0` because that method does not compute wrist twist.

### Evaluate Performance Metrics

```powershell
python -m server.common.evaluation.evaluate_performance_metrics dataset\pepper_singularity_motions
```

This writes a separate file:

```text
dashboards/results/performance_metrics.json
```

The script replays `annotations_filled.json` frames offline and measures the Chapter 4 system-performance metrics:

- `latency_ms`: per-frame method computation time.
- `latency_jitter_ms`: standard deviation of frame latency.
- `cpu_percent`: process CPU usage during method computation, as a share of total logical CPU capacity.
- `gpu_percent`: GPU utilization sampled through NVML, or `null` if unavailable.
- `memory_percent`: Python process RSS memory as a share of total system RAM.
- `memory_mb`: Python process RSS memory in MiB.

Sampling methods:

- GPU usage uses NVIDIA NVML through `pynvml`, specifically `nvmlDeviceGetUtilizationRates(...).gpu`.
- Memory usage uses `psutil.Process().memory_info().rss`, sampled before and after each frame method computation and averaged.

This is an offline benchmark of the IK/method computation only. It does not include camera capture, Metrabs inference, WebSocket transfer, or real Pepper command execution.

Use `--max-video-index 5` to benchmark only `video_001` through `video_005` in every selected category.

### Schema Migration

```powershell
python -m server.common.evaluation.migrate_annotations_schema <dataset-or-video-folder>
```

Use only if old annotation files need to be migrated to the current schema.

### Utility Scripts

- `create_synergy_videos.py`: webcam recorder for the `synergy_reference_motions` dataset category.
- `evaluate_performance_metrics.py`: offline replay benchmark for latency, jitter, CPU usage, and GPU usage.
- `craete_video.py`: utility for creating videos from frames. The filename is misspelled but kept as-is.
- `open_webcam.py`: quick webcam test utility.
